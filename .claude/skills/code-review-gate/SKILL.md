# Code Review Gate 质量闸门

每个 phase 收尾时强制执行。目标：**用可执行命令证明质量，而不是"看起来对"**。

## 1. 闸门检查项（全绿才算通过）

### 1.1 静态检查
- [ ] `npm run typecheck` 退出码 0（tsc 无类型错误）
- [ ] `npm run lint` 通过（ESLint 无 error）
- [ ] `npm run build` 退出码 0

### 1.2 行为验证（按改动范围执行）
- [ ] 受影响页面在 `http://localhost:31251/` 可正常渲染、无白屏
- [ ] 关键流程冒烟：涉及记账 → 新建一条 → 刷新页面 → 记录仍在
- [ ] 涉及 AI → 触发对应工具 → 数据正确落库
- [ ] 涉及课表 → 切周次 → 课程按模式正确过滤
- [ ] 涉及删除 → 确认弹窗出现 → 软删除生效（deletedAt 置位）

### 1.3 依赖与范围审计
- [ ] 无新增未经批准的 npm 依赖（对照 `studydesk-architect` 闸门）
- [ ] 未改动 `forbid_paths` 中的文件（对照 phase 合同）
- [ ] 未出现"顺手重构"的无关改动（diff 范围与 phase 声明一致）
- [ ] schema 字段未重命名/删除（只允许新增可选字段）

## 2. 审查输出模板

```markdown
## 审查结果
- Phase/变更：
- 静态检查：typecheck ✅ / lint ✅ / build ✅
- 行为验证：通过项 / 未覆盖项（说明原因）
- 范围审计：✅ 无越界 / ❌ 越界项清单
- 发现的问题：
  1. [严重/一般/提示] 描述 → 修复建议
- 结论：✅ 通过 / ❌ 需修复后重审
```

## 3. 规则

1. **先修复后合入**：发现的问题必须修复到闸门全绿，禁止带着已知 error 标记完成。
2. **如实报告**：未执行的验证项（如无法启动浏览器）要如实标注"未验证"，不默认为通过。
3. **反证优先**：主动寻找变更引入的回归，而不是只验证正向路径。
4. **一次一闸**：每个 phase 收尾跑一次，问题多轮修复后重跑，不跳过。
