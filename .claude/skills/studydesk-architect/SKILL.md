# StudyDesk 架构闸门

本 Skill 的唯一目的：**把架构决策钉死**，防止 AI 在每个会话里"重新发明"架构。
任何涉及技术选型、数据层、AI 工具协议、新增依赖的改动，必须先过本 Skill 的闸门。

## 0. 加载即生效的规则

1. **禁止静默改架构**：所有架构级变更必须先输出方案、等确认，再写代码。
2. **技术栈锁定表**（见 §1）是硬约束：标 ❌ 的层禁止变更，标 ✅ 的变更需先确认。
3. **Dexie schema 字段名是契约**：重构期间只允许新增可选字段，禁止重命名或删除已有字段。
4. **新增 npm 依赖需单独确认**：每引入一个依赖都要说明用途、体积影响、替代方案。
5. **只做当前任务**：不重构无关系统、不实现未来功能、不"顺手优化"未点名的代码。

## 1. 技术栈锁定表

| 层 | 当前 | 重构目标 | 是否允许变更 |
|---|---|---|---|
| 桌面壳 | Electron | 保持 Electron（不迁 Tauri，理由：现有 API 兼容性优先） | ❌ |
| 前端框架 | React 19 | 保持 | ❌ |
| 构建 | Vite 8（Rolldown）+ Tailwind CSS 4 | 保持 | ❌ |
| 数据层 | Dexie (IndexedDB)，软删除 deletedAt=0 | 保持 Dexie，统一走 repository 抽象层 | 部分 |
| 状态管理 | 组件内 useState + repository | 可引入 Zustand（仅 UI 会话态，持久数据仍走 Dexie） | ✅ 需确认 |
| AI 调用 | DeepSeek API，前端直调 + SSE 流式 | 收敛到 `src/modules/` 统一 AiGateway | ✅ 重构 |
| 路由 | HashRouter | 保持（Electron file:// 兼容） | ❌ |
| UI 系统 | 液态玻璃（components/glass + shadcn/ui） | 保持，token 化见 studydesk-ui-system | ❌ |
| 富文本 | Milkdown 7 + KaTeX + Prism | 保持 | ❌ |
| 图表 | Recharts（记账统计） | 保持，不混用 | ❌ |

## 2. 高风险决策确认闸门

遇到以下决策时，**禁止直接编码**。先输出 2–3 个可选方案（实现方式、影响面、风险、推荐理由），等确认后再进入设计文档：

- [ ] Dexie schema 迁移方式（是否保留软删除 deletedAt 策略）
- [ ] AI 工具协议是否从"前端直调"改为"通过 AiGateway 统一路由"
- [ ] 笔记 / 刷题模块是否引入虚拟滚动（当前数据量是否真的需要）
- [ ] 是否允许新增 npm 依赖（每引入一个需单独确认）
- [ ] 登录鉴权 / 权限模型（如未来引入多用户）
- [ ] 数据分页 / 导出协议的变更
- [ ] 导航来源与路由结构的变更
- [ ] 后端字段变更（当前无后端，涉及未来接口预留时同样确认）

## 3. 数据契约"唯一事实源"

核心资产是数据模型。规则：

- **字段名是契约**：`src/db/schema.ts` 中 29 张表（22 张基础表 + 5 张 quiz + 2 张 chat）的字段，重构期间只允许**新增可选字段**，禁止重命名或删除已有字段。
- 软删除策略：所有表统一 `deletedAt=0` 表示正常，`deletedAt>0` 表示已删。任何查询默认过滤 `deletedAt=0`。
- 数据访问：所有业务读写必须走 `db/repositories/*` 仓库层，页面不直接操作 Dexie。
- 聚合查询：跨表汇总走 `db/aggregate/*`（如 today 汇总）。
- 变更 schema 必须同时提供 Dexie `upgrade` 迁移逻辑，并验证旧数据无损。

## 4. 契约快照（变更前必须参照）

| 资产 | 位置 | 说明 |
|---|---|---|
| 表结构 | `src/db/schema.ts` | 29 张表定义（Dexie v1–v5） |
| 类型 | `src/db/types.ts` | 实体类型 |
| 路由 | `src/app.tsx` | HashRouter 全部路由 |
| 依赖 | `package.json` | 依赖与 scripts |
| 数据访问 | `src/db/repositories/*` | 仓库层 |

